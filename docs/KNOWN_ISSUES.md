## 一、平台限制（代码无法绕过）

### LIMIT-1 后台复制：LSPosed 已解决，纯无障碍路径仍受限
- **现状（2026-08-28 起）**：后台复制秒达已由 **LSPosed hook 剪贴板写入路径** 彻底解决（`ClipHook` hook `ClipboardManager.setPrimaryClip`，事件驱动、不读剪贴板、绕开焦点/读取豁免链）。无需切前台，微信/Chrome 等任意 App 后台复制均秒达电脑。
- **纯无障碍路径的历史限制（仍真实，作为 LSPosed 未启用时的兜底认知）**：ColorOS 严格执行 Android 10+ 焦点检查——非焦点 App 读剪贴板时 `hasPrimaryClip()` 返回 false；微信又不暴露 textSelectionStart/End，两条路都断，后台无解。
- **LSPosed 方案的前置与坑**：需用户装 LSPosed（KernelSU + Zygisk + LSPosed）；模块激活后须 force-stop 目标 App 再开（已运行进程不注入 hook）；ClipReceiver 的 intent-filter 不可删。
- **排错警示**：后台复制失败 ≠ 代码 bug。诊断历史里「系统未提供剪贴板（后台读取被拒或为空）」= 焦点限制的确凿证据（纯无障碍路径）；LSPosed 路径的诊断 tag 是 `ClipHook`/`ClipReceiver`。

## 二、缺陷（源码核实，尚未修复）

### DEF-4 Coordinator 状态机是半套死枚举
- `ClipboardMonitorCoordinator.State.STARTING / DEGRADED / ERROR` 从未被赋值（只有 RUNNING/STOPPED 在用）。误导后来者以为有降级检测。
- **处理建议**：要么接入真实信号（如 DEGRADED=无障碍在跑但 WS 断开），要么收敛枚举。

### DEF-5 直连发送路径不受 Dispatcher 过滤约束
- `ProcessTextActivity` 直调 `pushClipboard`、分享菜单直调 `sendText`，绕过 Dispatcher 的 autoSend 开关过滤与 Deduplicator。属用户显式动作，语义上可辩护，但与 D10 决策口径存在偏差；改造时并入统一管线，勿再新增第三条直连路径。

## 三、兼容性问题

### COMP-14 M45 手机麦克风的实验兼容与功耗边界

- M50已补分类恢复、精确ID重试、45秒校准兼容状态，以及显式节能连接。实机已验证节能释放系统录音/音频锁/音频FGS且保留素材WS、偏好跨进程保留、前台无需扫码重新开麦；用户确认本版手动与自动听写正常、手动停止后不自动恢复。本机虚拟线零空闲回调与恢复出声通过。手机电池A/B、真实首尾字及来电/撤权/锁屏/多ROM仍待专项验收；节能模式不支持后台按需开麦。详见[M50记录](performance/M50_AUDIO_RECOVERY_2026-10-18.md)。

- M44麦克风偏好自动保存，下次开启会话生效，活动会话不会因此重启。实机已验证开关/门限跨进程保留、本机采音服务实际读取抗噪-36；统一扫码/直接重连已改为同一读取路径，本轮未重新进行有声扫码听写。PC顶部波形只表示流转收到的PCM，不代表Codex已经识别。
- M43下拉面板已在原手机验证关闭/重新展开与试音持续，尚未实测真实大文件传输期间反复下拉；布局关闭不调用取消/停采。PC诊断是会话收到帧与播放回调读取统计，不证明录音端或ASR结果；没有输出读取能力的sink明确显示未知。
- 两端 v1.9.0 使用音频 WS8902；按用户要求未加密。邀请仅防误连接，不提供抵抗局域网窃听的保证。程序本身不自动更改防火墙、安装驱动或修改Windows默认设备；本机VB-CABLE是用户另行授权安装。
- 需用户安装并选对虚拟播放/录音端。自动跟随默认关闭且必须先校准，只支持可核验官方Codex包身份的独立录音会话；未知、跨进程归属、其他发行版、独占流及长期预开流可能不支持，使用手动转发。录音会话不区分同一Codex进程的听写/其他录音用途，不宣称直接监听原按钮。
- M42需两端更新才能在素材握手后协商麦克风。电脑按已保存设备或标准CABLE对启用音频；未安装驱动/设备已失效时需先配置，素材仍可用，之后手机点左上音波图直接重连，无需重扫。正常连接码不含短时音频邀请；新邀请通过已认证素材连接获取，单次/两分钟有效且不持久化。旧音频专用码仍为手动兼容路径。
- 明确扫码/点击连接后才开启采音；普通启动、历史素材连接和后台重连不自动开麦。拒绝权限后素材仍可用，已活动的手机麦克风不被新扫码强行替换。手机只允许一个录音会话，切换电脑或从本机试音切换前先结束原会话。
- 安静省流量按音量而非语义识别人声；底噪过大会保持发送，小声可能触发不了，应调灵敏度或使用连续模式。网络PCM省略与100ms批量读取已实现，实际功耗、首尾字、弱网和噪声环境需实机专项测量，不能承诺固定省电比例。手机仍采音检测、占用内置麦克风并维持有限期CPU锁。
- 原手机已完成本机采音、网络音频发送、CABLE实际输出和Codex原听写验收，用户确认识别正常；不同ROM与首尾字/锁屏/来电/功耗仍待专项验证。驱动安装器可能把Windows默认播放也改成CABLE；M46/电脑端1.9.1本地构建新增三路体检，分别检查日常/媒体/通信的播放与录音端点、选择缺失与失效状态，并提供固定Windows修复入口，不自动更改默认设备。体检不能证明每应用实际输入、虚拟线连通或听写结果。
- Android只支持内置麦克风；持续采音待命与暂停传输仍占用麦克风。M41按用户要求取消网络会话的15分钟/闲置限制，直至主动结束、断线、撤权或系统阻断；PC锁定/睡眠仍关闭音频服务。非引用计数CPU锁按20分钟续期、单次30分钟保险。真正停采后后台重开、跨 ROM 锁屏/来电、长时间稳定性、实际功耗和首尾字需要后续验证。不承诺硬实时停止；原生资源释放异常会阻止第二个采集器并提示重启应用。

### COMP-1 minSdk=36 只支持 Android 16+
Android 11–15 无法安装。降级为独立专项（见 DECISIONS D02）。

### COMP-2 覆盖安装 APK 后无障碍服务可能被系统禁用
每次交付需提醒用户到无障碍设置「关闭→重新开启」。App 内已有三态检测（`MainActivity.accessibilityState`：开关字符串/进程内 isRunning/框架绑定列表）区分「真没开」与「残留误报」，勿退回只读 Settings 字符串的方式。

### COMP-9 旧 LSPosed 对可调试进程的 instrumentation 注入兼容
- 2026-10-05 原手机 Android 16 / LSPosed Irena 1.9.2 (7249) 的 M32 可调试包在应用 onCreate 前原生崩溃，日志为 `Failed to init instrumentation` / `Failed to init lsplant`，SIGSEGV 帧在框架模块中。不可把停留的系统启动画面直接判成 Compose、连接或队列死锁。
- 日常安装使用 M33 起的不可调试 Distribution 包；保留正式签名和后台复制 Hook。Debug 只用于开发，旧框架中仍可能触发同一路径。此前正常到当前失败的具体 ART/框架变化【待确认】；关闭调试标记的现场对照只证明本机修复，不保证所有 ROM 的框架兼容。

### COMP-3 一加 Ace 3 Pro adb 连接困难
Windows 设备管理器完全看不到设备 = 线材（仅充电线）或端口问题，非软件问题；排查前先换数据线+直连+改 MTP。【待确认】ColorOS 对后台 Toast/通知吞没、开发者选项「禁止权限监控」等具体行为。

### COMP-4 PC 多屏混合 DPI 贴边仍需专项验证
- v1.3.1 已将贴边工作区换算为当前窗口 DIP，并取消鼠标换屏触发的窗口搬移；混合缩放跨屏实际表现仍待验证。仅修改系统缩放、未触发显示变化通知时，缓存的贴边位置仍需专项检查。
- M28 的离屏 150% 导出用于检查视觉布局，不等于真实高 DPI、多屏拖动或动画帧率验收。

### COMP-5 Android 同秒素材恢复位置的边界
- 协议时间为 Unix 秒，没有独立位置字段。Android 按素材时间排序，同秒沿用快照次序并记住最多 512 个近期删除位置；超出记录范围或跨快照恢复时，同秒项的精确位置不能仅靠既有字段完全还原，最终以权威快照为准。
- 独立 Repository 和实际 WS 检查覆盖序号连续性、删除/清空、重连及恢复，实机同步验收仍待进行。

### COMP-6 整理元数据的旧版本保存与手机范围
- 分组、标签和备注为电脑端 v1.5.0 的可选索引字段；旧素材库和迁移包能读取。旧电脑程序重新保存索引会丢弃未知字段，要保留整理信息请两台电脑均使用 v1.5.0 或更新版本。
- M49起Android支持在线单项收藏/分组/标签/备注编辑与实时增量；M52增加批量整理、加密离线索引及持久草稿、重连冲突处理。普通「另存」不包含这些内部字段，换机复用请用迁移包；手机离线索引和待同步草稿不进入迁移包。

## 四、技术债

### M51 容量清理与规模验证边界

- 回收只扫描已知托管目录的直接文件，最多10万；不自动清用户子目录、HEIC原件或续传状态。已有任务或撤回引用会阻止对应文件回收，目录链接/损坏记录保守停止。回收仍占空间，永久删除不可撤回；批次移动中断可部分完成，意图记录用于恢复，不等于系统事务。
- 安卓只清展示历史与缩略图内存，不删除下载文件。历史隐藏最多2万ID且异步保存，失败看日志；旧索引引用的文件、待发/暂停/重试和可靠回执保留。保留参数可迁移，trash/恢复状态不迁移。
- 大库排序缓存/摘要复用、批量Undo与缩略图预算已实施；手机1000条滚动摘要窗口，刷新或实时变更回到最新窗口。1千/1万/5万离屏布局与查询、128MiB中断并发、JVM恢复等只覆盖各自范围。物理混合DPI、多ROM/系统文件管理器组合、来电/锁屏以及真实弱网音频+大文件仍未整体验收；不将模拟DPI导出或回环传输当作这些场景通过。详见[M51记录](performance/M51_STORAGE_SCALE_2026-10-18.md)。

## 五、运维与构建注意事项

### OPS-1 构建环境
- 工程路径含中文无法编译 Android → 必须用副本 `F:/LiuzhuanApp`，改完同步后再 assembleDebug（完整命令见 AGENTS.md §二/§三）。
- F 盘偶发文件锁（安全软件瞬时占用）：编译失败报「拒绝访问」时 `rm -rf app/build` 重试即可；PC publish 前停 Liuzhuan.exe，发布后杀掉残留大内存 dotnet.exe（否则下次 build 报 MSB4018 / project.assets.json denied）。
- M57 使用 .NET 10 SDK（`global.json`）、AGP 8.10.1 / Gradle 8.11.1 / JDK 21 与 API 36。旧构建日志中的 API 36 插件警告不代表当前工具链；请先核对版本，不以忽略警告代替升级。

### OPS-2 部署要点
- `data/lan.json` 键为 `{Enabled, Port, Password}`，**Enabled 默认 false**（代码默认值）：全新环境部署 LAN 服务不启动且无明显报错，需先启用并配置口令。启动时的 TCP 自连自检 `LanServer.IsListening` 可用于判断 WS 是否真的在监听。
- 运行数据全部在工作区根 `data/`（非 `app/data/`），由 `ConfigService.GetEffectiveDataDir()` 解析 `exe/../data`。

### OPS-3 排查方法论速查
- **日志 tag 地图**（logcat 过滤用）：`ClipMonitor`(ACC 服务入口)、`ClipCapture`(DETECT/CAPTURE)、`ClipDispatch`(DISPATCH)、`ClipPipeline`、`PushToPc`(ACTION/WS/OUT_QUEUE)、`ClipCoord`(flush/VIS/装配)、`LanClient`(WS 状态/SYNC)。诊断不依赖 logcat 时看 UI 连接页「链路诊断/最近事件」（Coordinator 诊断 StateFlow，保留最近 6 条）。
- **A-B 对照法**：后台连续复制多条后切前台——全部发出 = 断线积压/队列问题（查 WS 连通性）；只发最后一条 = 平台焦点限制（属 LIMIT-1 范畴，不是 bug）。注意区分「前台重读剪贴板」（FG-fore 日志）与「队列 flush」（OUT_QUEUE flush 日志），两者现象相似、含义不同。
- 协议联调可不开真机：Python 模拟客户端直连 PC（scripts/ 下有现成脚本）。


### M29 / M33 真机验收范围
- 二维码使用实际 WLAN 地址，UDP 后台搜索、错误传播与取消释放通过自动检查。M33 已在原手机验证搜索发现电脑、扫码连接、三个页面切换、素材快照、手动发送及微信后台复制；旧二维码或已保存的虚拟网卡地址仍需重新扫码替换。尚未测量切页帧率，混合 DPI、多屏和不同 ROM/网络仍需独立验收。

### COMP-7 v1.7 功能范围与兼容
- 来源状态为最近显式检查的结果，不持续监控磁盘；旧程序已经移除的失效索引只能从旧备份恢复。手机暂未同步「原文件失效」标记，下载无法访问的文件会按原文件端点报告失败。
- 应用排除、临时暂停为每端本地设置；电脑迁移带排除名单，不带暂时期限，也不含手机应用偏好。旧电脑程序保存 appsettings 可能丢弃新字段，请两台电脑均使用 v1.7 或更新版本。
- 名单非空时未知来源自动采集跳过，可能使不暴露写入者的复制不进入历史；可用显式发送。已进入网络缓冲或已经发送的内容无法撤销，不承诺识别所有密码。
- 图片动作输出主图/首帧及无拍摄元数据的副本；动画、矢量和无法解码的文件会按处理界面说明输出/失败。真实 HEIC 样本、物理安卓设置页和后台复制仍待实机验证，取消无法立即中断单次 WIC 操作。

### COMP-8 v1.8 回执、完整性与预设的边界
- 自动文字队列最多 50 条，每条保留 5 分钟，最多提交 3 次；已提交但未确认时会明确结束。等待默认回执超时为 20 秒，旧服务器未声明幂等能力时不重发已接受请求。切换电脑、配对凭据或手机设备名会取消旧待发；已进入网络的内容无法撤回。
- PC 按已认证设备与请求编号保留 2048 条、10 分钟的登记结果，容量满拒绝新登记而不提前淘汰有效去重记录。此为旧协议兼容路径；M48 新设备身份路径使用持久回执，只有素材索引与回执均落盘才发送 durable ACK，手机加密恢复队列。
- 素材库 SHA-256 是用户主动确认的基线，结果只反映检查时读取内容；基线初次记录不能证明文件之前未损坏。检查后元信息或源版本变化要求重查，无法恢复原件，也不代替网络文件传输的端到端校验。
- 图片预设仅包含名称与格式/最长边/质量，不含输出目录；旧包没有预设仍可导入。损坏预设阻止空覆盖和空导出，显式重建会保留并校验副本。
- 离屏动效计时检查在并行编译负载下出现过一次时间断言失败，未改代码重跑通过；自动检查不代替真实 GPU、多屏 DPI 和手机触控验收。

### COMP-10 Android v1.8.2 功耗策略验收

### COMP-22 M57 恢复、离线原件与传输策略的边界

### COMP-23 M57 音频配置保护与实体声卡缺失

- 只有当前收到有效非静音PCM且虚拟播放端实际读取，才自动保存已验证的流转虚拟路由；这不能证明扬声器外放或听写识别成功。用户实测两者正常并确认后，才保存六路系统默认端点与外放音量/静音作为对照，异常/未知状态不覆盖好档案。
- 检查来自Core Audio设备、默认端点及音量事件，没有空闲周期轮询、试播放或试录音。正常改用耳机不直接当成错误；端点变化提示仍可能需要用户判断实际用途。
- 恢复只接受原精确ID，原设备消失、被禁用或驱动重装时不按同名设备替换。恢复先停止音频服务，只还原流转设备选择；Windows默认播放/录音、音量、静音、录音许可和自动跟随均不写入，也不会自动开麦。保护档案只留本机，不随迁移导出，不含录音或识别文字。
