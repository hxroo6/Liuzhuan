# 《流转》安卓版 · 5 阶段开发计划

> 日期：2026-08-03
> 配套定稿文档：`流转安卓版开发文档.md`（v0.2）
> 原则：每阶段可独立交付、可验收；阶段间有明确里程碑；先证明体验、再上复杂度

---

## 阶段总览

| 阶段 | 名称 | 核心交付 | 验收门槛 | 预估 |
|------|------|----------|----------|------|
| **M1** | 两端骨架 + 文本同步 | 电脑 LanServer + 安卓连接 + 文字秒达 | S1 达成 | 3~5 天 |
| **M2** | 文件传输 | 双向文件（照片/视频/任意） | S2/S3/S4 达成 | 4~6 天 |
| **M3** | 后台常驻 + 低功耗 | 前台服务 + 心跳 + 白名单 | S5 达成 | 3~5 天 |
| **M4** | 双向体验完善 | 电脑→手机推送 + 多设备 + 记录 | 全场景闭环 | 3~4 天 |
| **M5** | 发布 | 打包 + 文档 + 引导页 | 安装即用 | 2~3 天 |

> 预估为单人连续开发参考值。M1~M4 可滚动交付，每阶段结束都有可运行版本。

---

## M1：两端骨架 + 文本同步 ⭐ 最先做

**目标**：先证明「手机复制 → 电脑流转 2 秒出现」的体验成立

### 电脑端
- [ ] `Services/Lan/AuthService.cs` — sha256(口令) + ts 防重放
- [ ] `Services/Lan/WsHub.cs` — Fleck 监听 8899，会话管理
- [ ] `Services/Lan/LanServer.cs` — Start/Stop 生命周期，与 MainWindow 绑定
- [ ] 设置菜单「局域网服务器」：开关 / 端口 / 口令生成与显示 / 已连接数
- [ ] 收 `sync_text` / `clipboard_push` → CreateTextItem → Add → RefreshView（新增卡片样式）

### 安卓端
- [ ] 工程骨架：Kotlin + Compose + Material 3，单 Activity 3 Tab
- [ ] `net/LanClient.kt` — OkHttp WS：握手/心跳/重连（指数退避）
- [ ] `core/SettingsStore.kt` — IP/端口/口令/设备名持久化
- [ ] `ui/ConnectScreen.kt` — 连接卡片（输入 + 状态灯 + 一键重连）
- [ ] `ui/SendScreen.kt` — 文字输入发送 + 当前剪贴板一键发送
- [ ] `clipboard/ClipMonitorService.kt` — 无障碍监听复制 → 自动推送（基础版）

### 验收
- [ ] 手机复制任意文字 → 电脑流转 ≤2s 出现文字卡片（不手动操作）
- [ ] 错误口令 → auth_fail 提示；正确口令 → 自动接入
- [ ] 断网重连自动恢复（不手动）
- [ ] 手机端发送面板手动发送文字成功

### 交付物
电脑端可运行版（app 目录）+ 安卓 Debug APK

## M2：文件传输（双向）

**目标**：照片/视频/任意文件双向互通

### 电脑端
- [ ] `Services/Lan/FileChannel.cs` — HttpListener 8900：POST/upload、GET/download，1MB 分块 + offset 断点
- [ ] `Services/Lan/InboxSink.cs` — 落盘 data/inbox/ → sha256 校验 → 转正式素材（CreateFromPath → Add → RefreshView）
- [ ] `sync_file_meta` / `file_ack` / `transfer_done` 处理
- [ ] 右键菜单「发送到手机」（Pusher 推送文件元数据 + 提供下载）

### 安卓端
- [ ] `net/FileTransfer.kt` — 上传（SAF 流式分块 + 进度） / 下载（存 Download/流转）
- [ ] 发送面板：SAF 文件选择 + 系统相册选择器
- [ ] `share/ShareReceiverActivity.kt` — 系统分享菜单入口（ACTION_SEND：文字/图片/任意文件）
- [ ] Tab2 同步记录：文字预览 / 缩略图 / 时间 / 进度条

### 验收
- [ ] 手机相册选 10MB 照片 → 电脑流转出现缩略图，全程进度可见
- [ ] 手机发 1GB 视频不崩（流式），中途断网可续传
- [ ] 任意 App「分享 → 流转」→ 送达电脑
- [ ] 电脑右键「发送到手机」→ 手机收到可保存
- [ ] 同 sha256 重复发送 → 电脑端秒跳（exists 去重）

### 交付物
双向文件可用的完整版

## M3：后台常驻 + 低功耗

**目标**：S5「后台 8 小时耗电 ≤2%」达标

### 安卓端
- [ ] `core/AppForegroundService.kt` — foregroundServiceType="dataSync"，通知常驻
- [ ] 心跳自适应：30s ↔ 5min（空闲升档）
- [ ] Doze 引导：Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS
- [ ] 厂商后台限制引导页（小米/华为/OPPO/vivo 设置入口映射表）
- [ ] 剪贴板监控完善：防抖（2s 同内容）、去重、空内容过滤
- [ ] 网络变化广播（CONNECTIVITY_CHANGE）→ 立即重连

### 电脑端
- [ ] 会话超时清理（心跳超时踢掉死会话）
- [ ] 多手机并发压力测试（3 台同时在线）
- [ ] 端口占用处理（被占用时提示 + 自动选备用端口）

### 验收
- [ ] 黑屏 + 无操作 8h → 耗电 ≤2%（实测）
- [ ] 复制文字仍秒达（后台状态）
- [ ] 杀前台应用后（白名单模式）连接自动恢复
- [ ] 3 台手机同时连接互不干扰

### 交付物
可日常使用的稳定版

## 阶段依赖与顺序理由

```
M1 文本同步（体验验证） ← 最小成本证明核心价值
  ↓
M2 文件传输（价值放大） ← 素材大头在图片/视频
  ↓
M3 后台低功耗（信任）   ← 不常驻就没有"流转"的意义
  ↓
M4 双向打磨（闭环）    ← 依赖 M2 的文件通道
  ↓
M5 发布（交付）
```

> 每个里程碑完成后建议实际使用 1~2 天再进入下一阶段，及时反馈调整。
> 若 M1 体验不达标，先修 M1 再继续，避免带病叠加复杂度。
