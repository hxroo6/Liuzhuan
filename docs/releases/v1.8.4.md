## 中文

本次发布 Android v1.8.4（versionCode 9）与 PC v1.8.1，包含 v1.8.1 之后的性能、收发任务和接收目录改进，两端协议保持兼容。

### 安卓接收与收发
- 图片、视频、音频和其他新接收文件统一保存到**内部存储 / Download / Liuzhuan**，首次接收时创建目录。已有文件保持原位置。
- 「打开接收目录」直接调用系统文件管理器浏览固定位置，不弹出目录选择或授权界面。可配置支持目录浏览的管理器；不支持时明确提示更换应用，不回退到选择器。目录定位和图库索引取决于设备 ROM。
- 收发页改为全屏，支持全部 / 进行中 / 已结束筛选；任务提供暂停、继续、取消和失败重试。安卓暂停停止当前 I/O，保留来源，继续会**从头传输**；任务仅保留在当前进程。

### 安卓性能与功耗
- 新增可选「均衡省电」，默认关闭，保留即时同步策略；开启后空闲允许休眠，任务期间临时保活。实际耗电变化与锁屏到达延迟需要实机对照，不承诺固定省电比例。
- 保活锁幂等获取及释放；修复失败重连退避计数，感知局域网路由，连接由进程持有，页面重建不重复建连。
- 图片 Hook 改为有界后台读取与 512 KiB 硬上限；HTTP 客户端共享资源，文件传输并发受限，取消实际网络请求。缩略图、素材同步、进度和诊断更新减少无效工作。
- 保留事件驱动后台复制、进程级发送作用域、隐私检查、防循环及正式签名；日常交付为不可调试的 Distribution。

### 电脑收发
- 收发窗口扩大至 840 × 680，可调整大小；提供接收目录、逐项保存位置和自定义文件管理器 EXE / `{folder}` 参数。
- 文件任务支持暂停、继续和取消。暂停仅保留当前连接，最多 90 秒；断线或超时须重传。取消终止 I/O 并清理未完成上传，不撤回已登记素材。
- **两端尚不支持真正的字节偏移断点续传，也不支持跨进程恢复任务。** 已提交文字和进入登记阶段的文件无法撤回。

### 下载与升级
- `Liuzhuan-v1.8.4-android.apk`：Android 16+，正式签名，覆盖安装后到无障碍设置**关闭→重新开启**流转服务。LSPosed 用户保留模块与目标应用作用域，并重启目标应用进程以载入新版 Hook。
- `Liuzhuan-v1.8.1-windows-x64.zip`：Windows 10/11 x64，自包含；解压运行 `app/Liuzhuan.exe`。先退出旧流转，再替换整个 `app`，保留同级 `data`；程序包不包含用户素材和配置。
- `Liuzhuan-v1.8.4-SHA256SUMS.txt`：使用 `Get-FileHash -Algorithm SHA256` 校验下载。

验证：M34 功耗与相关链路 198 项、M35 收发与相关链路 150 项、M36 目录修订 23 项本地检查分别通过（各阶段检查有重叠，不相加）；最终 Android Debug / Distribution / lint 与正式签名检查通过，PC 已构建并验证收发。最新改动没有本轮手机实机耗电或目录定位验收；此前版本的实机通过不代替这次验收。详情见仓库 `docs/performance/`。

已审计当前公开源码和程序包，不含个人联系方式、设备地址、配对口令、手机日志、用户素材、配置、备份、PDB 或签名私钥；示例和隔离测试网络地址仅为测试数据。自行导出的迁移包包含素材及口令，未加密，请私下保管。已有 Git 历史和旧版 Releases 保留。

## English

This release includes Android v1.8.4 (versionCode 9) and PC v1.8.1, delivering performance, transfer-task and receive-folder improvements since v1.8.1. The existing protocol remains compatible.

### Android receiving and transfers
- All new downloads, including images, videos and audio, go to **Internal storage / Download / Liuzhuan**. The first download creates the folder. Existing files remain in their original locations.
- "Open receive folder" opens the fixed location in a system file manager, without a folder-selection or permission picker. A compatible directory browser can be configured. Unsupported browsers show a message instead of falling back to a picker. Directory navigation and gallery indexing depend on the device ROM.
- Transfer tasks use a full-screen view with All / In progress / Finished filters, pause, continue, cancel and retry. Android pause stops current I/O and retains the source; continuing **restarts the entire transfer**. Tasks exist only in the current process.

### Android performance and power
- Optional Balanced mode is off by default, preserving immediate sync. It allows idle sleep and holds resources temporarily during work. Battery savings and screen-off delivery latency require device comparison; no fixed savings are promised.
- Keep-alive locks are acquired and released idempotently. Retry backoff retains failure counts, LAN route changes are observed, and the process owns connections instead of reconnecting on activity recreation.
- Image Hook reads use bounded background work and a 512 KiB hard limit. Shared HTTP resources, bounded transfer concurrency and cancellation of actual requests reduce unnecessary work. Thumbnail, material-sync, progress and diagnostic updates are more efficient.
- Event-driven clipboard capture, process-level sending, privacy checks, loop prevention and the production signing certificate remain intact. The release APK is non-debuggable Distribution.

### Desktop transfers
- The transfer window is enlarged to 840 × 680 and remains resizable. Open receive folders or individual saved locations, or configure a file manager EXE with a `{folder}` argument template.
- File tasks offer pause, continue and cancel. Pause retains the current connection for up to 90 seconds; connection loss or timeout requires retrying. Cancel stops I/O and removes incomplete uploads, without recalling registered materials.
- **Neither side supports byte-offset resume or task recovery across process restarts.** Submitted text and files already entering registration cannot be recalled.

### Downloads and upgrade
- `Liuzhuan-v1.8.4-android.apk`: Android 16+, production certificate. After replacement, toggle Liuzhuan accessibility **off and back on**. Keep LSPosed module scopes enabled and restart target app processes to load the updated Hook.
- `Liuzhuan-v1.8.1-windows-x64.zip`: Windows 10/11 x64, self-contained. Extract and run `app/Liuzhuan.exe`. Exit the old app, replace the entire `app` directory, and preserve the adjacent `data` folder. No user materials or settings are included.
- `Liuzhuan-v1.8.4-SHA256SUMS.txt`: verify downloads using `Get-FileHash -Algorithm SHA256`.

Validation: M34 passed 198 local checks, M35 passed 150, and M36 passed 23. These stages overlap and are not an additive total. Final Android Debug / Distribution / lint and production-signature checks passed; PC transfer builds and checks passed. The latest changes have no current device battery or directory-navigation acceptance. Earlier device results do not validate this update. See `docs/performance/`.

Current public source and packages were audited for private content. Personal contacts, device addresses, pairing credentials, phone logs, materials, settings, backups, PDBs and signing private keys are excluded. Example and isolated-test network addresses are test data. User-created migration archives contain materials and credentials without encryption; keep them private. Existing Git history and older releases remain available.
