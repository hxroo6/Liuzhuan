# M41：合并扫码、安静省流量、持续待命与实验自动跟随

版本：两端 `1.9.0-preview.3`，Android versionCode 14。仅本地交付，公开 Release 不变。

## 使用

1. 电脑设置 → 手机麦克风，选择已确认相连的虚拟端点：流转写入 CABLE Input，Codex 读取 CABLE Output。Windows 系统播放使用实体扬声器，避免其他声音混入虚拟录音。设备ID会保存在当前电脑，失效时需重新选择；不保存自动运行许可。
2. 开启音频服务，同时开启原素材服务。原配对窗口和麦克风窗口均可生成合并码；手机从任一扫码入口读取后连接素材，并显示麦克风确认页。扫码不采音，必须主动确认并授权。音频邀请两分钟/一次有效，到期刷新；素材字段不随邀请到期失效。
3. 手机默认“安静省流量”，可选灵敏/标准/抗噪，或取消勾选使用连续传输。确认“开启麦克风 · 持续待命”后，不再有15分钟或闲置一分钟限制；安静和停止转发均不释放采集器，直到主动结束或链路/系统中断。
4. 手动模式在电脑开始转发，再用 Codex 原听写。实验自动模式先点“校准原听写”，保持听写关闭片刻，再开始一次约三秒的听写并结束；校准通过且手机采音待命后，勾选自动跟随。校准不自动发送音频。
5. 手机暂停、电脑手动停止、连接或身份变化都会退出自动跟随；恢复需重新确认开启。结束手机会话才释放采集器。断线不恢复录音，电脑锁定/睡眠仍关闭音频服务。本机试音仍60秒，不连接电脑。

## 音量门控与功耗边界

- 检测PCM RMS音量，默认-42dBFS；灵敏-48、抗噪-36。连续40ms达到阈值开启，关闭阈值低6dB并保留500ms尾音，避免临界底噪频繁切换。200ms开头环形历史有界保存在内存，换代/停止清除，不落盘或跨许可复用。
- 安静时不发送PCM，仅维持既有1Hz状态/租约与低频WS保活。有声时恢复20ms帧；安静或后台无转发需求时批量读取100ms，减少应用层读取次数。理论原PCM消息为每秒50×684字节，安静门关闭时该部分为0，心跳与网络协议仍有开销。
- 这不是人声识别：风声、音乐、敲击和持续噪声都可能触发；小声可调灵敏或关闭门控。手机仍持续采音，CPU锁使用非引用计数，单次30分钟且健康会话每20分钟续期，结束清理；不承诺固定电量收益或无麦克风占用。
- `welcome.data.silenceSuppression=true`才启用省流量，旧电脑回退连续发送。当前代次`status.quiet=true`使电脑清输出缓存、放宽无帧检查；恢复只认合法PCM。声称有声但没有音频仍超时，心跳缺失仍断开，避免以静音掩盖失联。

## 自动跟随实现边界

- 只观察所选录音端的Windows会话，不拦截鼠标、键盘、Codex界面或识别内容。
- 原始`GetProcessId`必须S_OK，并核验官方Codex包家族、进程路径和创建时间；不按名字放行任意同名进程，不接受跨进程成功码。会话实例去重、回调有界入队、MTA工作线程每200ms检查已跟踪状态。
- 用户校准通过后仅绑定本次手机连接和停止修订；命令在服务器锁内再次核对，防止检查后换连接。最后录音会话空闲400ms停止。未知归属、端点失效或观察过期退出，不猜测按钮。
- 同一进程的其他录音用途可能无法与听写区分，独占或长期预开会话也可能不支持；可保留手动桥接。设置窗口关闭不停止用户已启用的观察/转发，主程序退出仍清理。
