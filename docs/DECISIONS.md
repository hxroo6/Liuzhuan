# DECISIONS — 仍然有效的设计决策

> 只收录经源码核实**当前仍然有效**、且改动会引发回归或故障的决策。
> 每条包含：决策内容 / 原因（含历史依据）/ 当前源码锚点 / 改动约束。
> 已被推翻的历史方向不收录于此（见 `logs/项目迁移交接文档_20260827.md` §3 与 git log）。

## D01 debug 构建使用 release 签名

- **决策**：debug、distribution 与 release 共用同一 keystore 签名；日常交付使用不可调试的 distribution（见 D33）。
- **原因**：签名不同会导致覆盖安装需先卸载 → 无障碍授权被系统清除。同签名可直接覆盖升级。
- **锚点**：`AndroidApp/app/build.gradle.kts` 的 `buildTypes.debug.signingConfig`；keystore 在 `AndroidApp/keystore/`（gitignore）。
- **约束**：不能改回默认 debug 签名；keystore 文件丢失时新环境需重建或恢复。

## D02 minSdk = 36（只支持 Android 16+）

- **决策**：三端 SDK 版本锁定 36。
- **原因**：`AccessibilityServiceInfo` 在 API 36 从 `android.view.accessibility` 迁移到 `android.accessibilityservice` 包（无障碍三态检测代码已用到后者），锁定可免兼容分支。
- **约束**：降级是独立专项——需处理包路径分叉与各 API 差异，不允许顺手改。

## D03 双服务分工架构

- **决策**：无障碍服务（ClipMonitorService）只负责感知复制事件；前台服务（ForegroundService）只负责保活（Wi-Fi/CPU 锁）。
- **原因**：职责分离避免前台服务读剪贴板/轮询的合规问题，也让保活生命周期独立于监控状态。
- **锚点**：`ForegroundService.kt` 全文无剪贴板逻辑；`LanController.onState` 控制其启停，Activity 只订阅进程级状态。
- **约束**：两条边界都不能越——前台服务里加采集逻辑、无障碍服务里管连接都属于越界。

## D04 评分模型基线（M10→M13 的教训固化为规格）

- **决策**：
  1. 第三方 App 的 `WINDOW_CONTENT_CHANGED` = **MEDIUM**（触发 selection 捕获 + debounce 剪贴板兜底）；
  2. SystemUI/Launcher 的 `WINDOW_CONTENT_CHANGED` = **NONE**；
  3. 第三方 `TEXT_SELECTION_CHANGED` 与命中「复制」文案的点击 = HIGH。
- **原因**：微信等 App 复制只产生 WINDOW_CONTENT_CHANGED（不暴露 selection 变化事件），MEDIUM 是它们唯一的检测入口（M6 生效路径）；M10 曾把它降到 LOW 导致 capture 完全不执行，M13 恢复。SystemUI/Launcher 弱信号是高频假阳性主来源（反向教训同样成立）。
- **实测边界（2026-08-27 adb 确认）**：MEDIUM 的捕获在本机 ColorOS 上仅前台有效（焦点就绪时 selection/剪贴板都可命中）；流转后台时 selection 不暴露 + 剪贴板被焦点检查拒绝，两条捕获路都被关死。「不切回流转的后台自动发送」在严格执行焦点限制的 ROM 上无解（见 KNOWN_ISSUES LIMIT-1），微信场景走文本选择菜单或切回流转发。MEDIUM 基线保留的意义：前台事件驱动路径 + 对焦点限制宽松 ROM 的兼容。
- **锚点**：`CopyEventDetector.evaluate`。
- **约束**：调优评分时两个方向的基线都不可动；消除假阳性只能加更精确的分类规则，不许整体降级。

## D05 循环回写防护用 markLocalText（双入口）

- **决策**：本 App 写入手机剪贴板的每个入口都必须随后调用 `ClipboardMonitorCoordinator.markLocalText(text)`。
- **原因**：PC 推来的素材复制到手机后若无防护，无障碍会再读到相同内容回推 PC 形成死循环。指纹被记入 Deduplicator 后即可抑制回推。
- **锚点**：`MainActivity.copyToClipboard`（接收页点击素材复制）+ `ProcessTextActivity.onCreate`（选择菜单顺带写剪贴板）。两处缺一不可。
- **约束**：新增任何写剪贴板代码路径必须带 markLocalText。

## D06 发送链协程作用域全部进程级 SupervisorJob

- **决策**：`ClipboardCaptureManagerImpl` / `ClipboardActionPipeline` / `LanClient` 的 scope 一律 `CoroutineScope(SupervisorJob() + Dispatchers.x)` 默认参数。
- **原因**：后台复制的捕获→分发→发送必须不依赖 Activity/ViewModel 存活。
- **约束**：改成生命周期 scope 会静默失效（编译期无错）；新增后台组件沿用同一模式。

## D07 断线缓存与回执队列由单一发送器消费

- **决策**：自动文字进入 `ClipboardEventQueue`(FIFO max 50)，由进程级 `AutomaticClipboardDelivery` 单一发送器推进；Action 只提交，Coordinator 的重连通知只唤醒，不再双路径 drain。
- **原因**：网络发送与捕获解耦，断线不丢件也不阻塞监听。
- **原因补充**：旧 drain 原子取走避免了双 flush 竞争，但在收到回执前移除会丢失失败事件。v1.8 以稳定请求编号、原子队列更新和单一发送器替代，回执/重试状态不混用旧 drain 逻辑。
- **约束**：发送器外部不消费自动队列；提交前安装关联，回执移除后不得重新写入等待状态。每次提交重查隐私与目标，过期、满队列和有限尝试结束须报告；协议约束见 D30。

## D08 接收页单一事实源：StateFlow + collectAsStateWithLifecycle

- **决策**：PC→Android 同步数据只落在 `MaterialRepository`（object 单例 StateFlow），UI collect 主线程呈现；WS 回调只调 Repository 方法。
- **原因**：旧方案（OkHttp 回调线程直接写 mutableStateListOf 作 UI 唯一数据源）脆弱且违反单向数据流，M7 重构废弃。
- **约束**：不允许在 Screen 层自建列表状态承接 WS 增量。

## D09 事件驱动取代轮询

- **决策**：无障碍事件驱动检测 + 捕获失败自然结束（最多三次短延迟重试共 ~260ms），无定时器。
- **原因**：后台读剪贴板受焦点限制，轮询既耗电又读不到，M6 已删除 2s 轮询。
- **约束**：「禁止恢复剪贴板 polling」；注意区分概念——HIGH 触发后的 80/160/260ms 短延迟重试是「事件后的等待更新」，不是轮询，勿当轮询清理。

## D10 捕获事件统一出口为 Dispatcher（含已知例外）

- **决策**：所有**捕获产生**的事件必须产 `ClipboardEvent` 经 `ClipboardEventDispatcher.dispatch` 过滤/去重后再进入 ActionPipeline；禁止捕获层直接调 WebSocket。
- **已登记例外**：`ProcessTextActivity`（选中文本直发）与分享菜单文字（`sendText`）是用户显式动作直连 LanClient，不经 Pipeline —— 属于「用户指令优先于自动链路开关」，不是缺陷模式；但改造它们时应并入统一管线而非扩散第三条直连路径。
- **约束**：给 Dispatcher 加过滤条件时明确它不影响上述直连路径（例如 autoSend 开关目前拦不住 ProcessText 直发，这是接受的行为还是 bug 见 KNOWN_ISSUES DEF-5）。

## D11 后台复制秒达的唯一解：LSPosed hook 剪贴板写入路径

- **决策**：接受 Android 10+ 后台剪贴板「读取」焦点限制（ColorOS 豁免链仅 IME/焦点 App/SystemUI/privileged/READ_CLIPBOARD_IN_BACKGROUND）。**后台复制秒达靠 LSPosed hook 剪贴板「写入」路径**（`ClipHook` hook `ClipboardManager.setPrimaryClip`，事件驱动、不读剪贴板、绕开全部读取豁免链）；前台主动重读 + 文本选择菜单（ACTION_PROCESS_TEXT）作无 LSPosed 环境的兜底。
- **原因**：ColorOS 对「读」做了 checkPackage/焦点多重拦截（root daemon 也被 `SecurityException: Package android does not belong to 2000` 拒死），但「写」不受这些限制——hook 写入路径是唯一能 100% 捕获任意 App 后台复制的方案。
- **锚点**：`xposed/ClipHook`、`ClipReceiver`、`ProcessTextActivity`、`captureOnForeground`。
- **约束**：LSPosed 需用户装框架（KernelSU + Zygisk + LSPosed，本机为 Irena fork）；ClipHook 只旁路观察、不改返回值、不抛异常；ClipReceiver 的 intent-filter（action=com.liuzhuan.app.ACTION_CLIPHOOK）不可删。

## D12 Hub 信任模型：口令即权限，明文局域网

- **决策**：电脑端=服务器；凭 6 位数字口令自动接入（无逐台弹窗确认）；传输明文（WS/HTTP/UDP），安全手段=sha256 口令哈希 + ts 防重放 + HTTP 层同套鉴权。
- **原因**：局域网场景下简单可靠优先（2026-08-03 开发文档定稿决策 #5/#6，其余仍有效部分一并沿用：Hub 模式、Fleck、分享菜单截图路径）。
- **约束**：升级加密/配对流程属协议级变更，两端同步设计。

## D13 文件数据面手写 TcpListener HTTP

- **决策**：8900 数据面是 `FileHttpServer` 手写极简 HTTP（TcpListener），不用 http.sys/Kestrel。
- **原因**：规避 http.sys URL ACL 权限坑与重依赖。
- **约束**：扩展端点时保持鉴权一致性（auth 参数校验放最前面）。

## D14 同步语义：全量快照 + 三类增量广播 + sequence gap resync

- **决策**：连接成功先拉 `list_data` 快照；此后 Add/Remove/Clear 分别广播三类增量，Android 统一先验序，缺口不应用变化而请求一次快照；重连和序号 0 的快照重置基线。
- **原因**：取代 v0.2 设计「仅新增」（M7 起实现删除/清空联动）；gap 检测兜底丢消息场景。
- **约束**：PC 的快照序号来自 CurrentSequence，即使空库也保留；捕获列表和排入回复必须在同一次素材所属线程调度中，防止新增量先于旧快照。时间与序号用途分离，序号代表变化，撤回不能因此把旧素材置顶。

## D15 多设备模型与同名设备会话替换

- **决策**：服务端全局广播所有变更给全部会话（多台手机天然一致）；同一 device 名重连时踢掉旧 session 再建新 session。
- **原因**：安卓 Activity 重建/闪退重连会产生叠加会话，导致设备列表脏数据与重复广播。
- **锚点**：`WsHub.HandleHello` 中 oldKey 清理逻辑。
- **副作用认知**：手机自己推送的文字也会经 DataStore.Add 广播回自己（含广播语义的自然结果，接收页能看到自己刚发的条目，属预期行为）。

## D16 收发状态以实际完成阶段为准（M27）

- **决策**：上传收齐文件并登记后才确认；手动文字在登记回调完成后返回带 requestId 的 ack。手机保存成功必须等 MediaStore 文件关闭及 IS_PENDING 清除，PC 写出文件只能显示「已发送」。
- **原因**：提交到网络缓冲、服务器接收与手机落盘是三个不同阶段，不能都显示为已送达；未收完整的文件不得进入素材库或相册。
- **约束**：保持 `Proto.kt` / `WsHub.cs` 字段同步，保留原剪贴板进程级作用域。任务记录限本次运行，失败由用户手动重传；未确认的上传可能已到达，重试前提示核对，不能承诺去重或断点续传。预览与缩略图独立于原素材，鉴权与文件端点一致。

## D17 动效服务于状态反馈，不改变业务与命中（M28）

- **决策**：反馈短、面板略长，所有动效可被新操作替换并跟随系统动画设置。关闭动画时同步设置最终状态并执行完成逻辑；连续反向不能让旧回调缩起新面板。
- **原因**：跟手与状态稳定优先，动画不能阻止点击、重复发起传输或重建整页素材。快速操作、低性能设备和关闭动画均需有明确结果。
- **约束**：PC 卡片只变换内部视觉层；Android 页面不使用双份内容承载业务副作用。禁止给所有卡片挂持续动画或以延迟完成提示模拟传输进度；真实帧率与触感须在设备上验证。

## D18 发现流程不能阻塞界面，连接地址必须来自可用 LAN（M29）

- **决策**：二维码过滤隧道和虚拟网卡并提供候选选择；发现响应考虑请求者子网，Android 优先采用回包源地址。所有 UDP 操作在 IO 调度器执行，异常显示在连接页，取消时释放 socket。
- **原因**：虚拟网卡地址曾被选入二维码，手机所在的物理局域网无法访问；原搜索直接在 Compose 主线程发送 UDP 且没有异常处理，存在闪退路径。
- **约束**：不把全部 172.* 地址当作虚拟网络，不自动改用户 VPN 或防火墙。二维码无法预知手机接入哪张网卡，多网卡需用户选择；接收列表采用懒加载，整页动画不作为切页的必要步骤。核心剪贴板作用域和服务保活保持原约束。

## D19 迁移先完整校验，再于下次启动切换独立库
- **决策**：导入不向现有 DataStore 逐条写入，也不在运行中直接切 ConfigService 路径；先在新目录解包并重建路径，再记录 pending，下次启动切换并保留原配置指针。
- **原因**：DataStore 保存路径是动态计算且有延迟保存，运行中切换会让旧内存索引覆盖新导入的数据。普通素材收集只保存绝对路径，迁移必须包含文件字节，不能直接复制旧 data.json。
- **约束**：不能复制旧电脑目录路径或自启命令；只能重新应用声明的设置。ZIP 只允许清单引用的文件，导入完成前必须验证大小和哈希，取消/失败不激活。迁移包包含配对口令，UI 必须明确告知。

## D20 动画取消必须覆盖尚未启动的队列任务
- **决策**：UiMotion 为每个 DependencyObject/DependencyProperty 管理版本，排队启动和完成回调都校验版本。零时长、禁用动画、目标值相同也必须使前一操作失效。
- **原因**：仅 BeginAnimation(null) 只能停止已安装的时钟，不能停止 Dispatcher 队列中等待启动的动画；旧 Completed 还能先写回旧目标，绕过面板层的业务回调保护。
- **约束**：窗口拖动期间先固定展开布局再进入 DragMove，不允许热区或收起逻辑在嵌套消息循环中改动窗口；退出拖动统一恢复。不能以强制软件渲染或持续重绘代替状态修复。

## D21 素材另存与换机迁移分别保存内容和配置
- **决策**：选中另存使用普通文件和 UTF-8 文本，不写配置或内部索引；先捕获快照，后台复制到新建独立目录。同名编号、缺失来源或取消不报成功。
- **原因**：用户整理一组素材需要可直接使用的文件，而换机迁移要完整恢复配置与索引，沿用 D19 的迁移包流程。
- **约束**：来源始终只读；取消/失败仅尽力清理自身输出，不能递归删除用户目标目录。带 FilePath 的文字必须复制原文件，不能把截断预览当全文。连续字节进度需节流，避免大文件复制把界面队列塞满。

## D22 撤回和部分清空必须同步实际变化
- **决策**：每个恢复/删除增量都有独立 sequence；Undo 发 ItemAdded，部分清空发 ItemRemoved，仅空库发全局 ItemCleared。
- **原因**：仅本地恢复会让手机素材缺失；保留收藏或其他分类时发全局 clear 会错误移除手机所有素材。
- **约束**：恢复不更新时间，保持原位置及收藏等元数据，同 ID 已存在则跳过；不扩展现有协议字段。Android 同秒恢复的位置边界见 KNOWN_ISSUES。

## D23 整理元数据保留未修改字段并随素材迁移
- **决策**：每条素材一个可选分组、多标签和备注；补丁字段 null 表示保留，空值表示清除。批量标签支持追加/替换/移除，先完整校验再写入。
- **原因**：批量编辑不能把未勾选字段或不同素材的旧信息统一清空；换机后应能继续使用相同整理信息。分组来自素材，避免引入与素材分离的空分组状态。
- **约束**：编辑和导入共用长度/字符校验，不能静默截断；单个标签不得含编辑器分隔符。整理不改原文件和时间、不发送无意义的 LAN 增量。普通另存保持内容文件语义，迁移包包含元数据。

## D24 筛选后的清空范围取当前可见结果
- **决策**：确认前捕获当前可见 ID，一般视图保留收藏，收藏页只取消收藏；工具模态窗口使用独立的自动收起保护。
- **原因**：新增元数据筛选后，按分类清空会误删隐藏素材；右键菜单关闭不代表其打开的编辑窗口已经关闭。
- **约束**：不删除源文件，沿用 DataStore 批量删除、撤回和实际 ID 广播；模态窗口退出时恢复收起计时器。

## D25 常用筛选保存条件并随素材库迁移
- **决策**：保存分类、分组、标签和搜索条件，不保存一次性 ID 集合；规则文件属于素材库，作为可选配置加入迁移。
- **原因**：用户反复找同类素材不应重复设置条件；新素材应该自动进入匹配的视图。删除规则不能变相移除素材。
- **约束**：名称、数量与条件统一校验，失败不改内存或原文件，损坏规则文件明确提示并保留；旧迁移包兼容。

## D26 发现端口固定，连接端口在应答里协商
- **决策**：UDP 发现固定 8901，OFFER 携带实际 WS 端口；使用单个监听，保持旧 Android 兼容。
- **原因**：发现客户端未连接电脑，无法预知自定义端口；把发现端口设为 WS+2 会让自定义连接端口静默破坏搜索。
- **约束**：不修改用户网络/防火墙；生命周期任务持有本次 socket/token，不以可变字段读取实例。IO、单调超时及取消释放保持有效。

## D27 失效来源保留索引，重定位只在审阅确认后应用
- **决策**：缺失来源是可见状态，不是删除理由；文件夹候选只供检查，单项/批量全部验证后更新现有素材。
- **原因**：外部改名、移动和磁盘暂时失联不应抹掉收藏/标签/备注。同名同大小不等于同内容，错误绑定比未修复更难察觉。
- **约束**：不删原件，不改 ID/时间/位置；过期检查与缩略图回调不得覆盖新路径。扫描后台、可取消、有上限、跳过链接，超限/歧义明确报告。

## D28 自动采集隐私规则与显式发送分开
- **决策**：暂停和应用排除在读取/解码与发送前生效；来源未知且名单非空时保守跳过，手机旧自动事件随规则版本失效。
- **原因**：仅在设置页改开关不能约束异步捕获、断线队列及文件旁路；系统事件的前台包名不一定是剪贴板写入者，不能承诺识别所有敏感数据。
- **约束**：不改变评分/进程 scope/Hook/保活，不阻止用户明确发送或接收，不自动删历史。配置错误阻止自动采集，保存失败不假报成功，临时期限不随电脑迁移。

## D29 图片处理生成独立副本并明确变换边界
- **决策**：后台批量输出 PNG/JPEG，尺寸只缩小，JPEG 透明白底；落实 EXIF方向，首帧输出并清除拍摄元数据。
- **原因**：图片交付常需改尺寸和格式，不能覆盖原件或把改变后的字节冒称原素材；编码质量不保证输出一定更小。
- **约束**：独立输出目录、同名编号、逐项结果；尺寸解码有界，取消清理仅自身文件且非递归。动画、矢量、HEIC解码器和原生操作取消边界在 UI 明示。

## D30 自动文字以登记回执确认，重试需要协商与幂等
- **决策**：自动文字使用稳定请求编号，等待电脑登记回执；只有服务器明确支持幂等回执时才有限重试。旧端只提交一次，未收到回执明确显示未确认。
- **原因**：OkHttp send 成功只表示排入发送缓冲，不能证明电脑收到；盲目重试会把同一条内容登记多次。
- **约束**：进程级任务、隐私来源/版本/期限与目标电脑约束不能绕过；队列、尝试次数、期限和服务器缓存有界。登记回执不承诺磁盘事务持久化，进程重启或缓存淘汰后不承诺永久恰好一次；不变更 Hook、评分、保活与显式发送语义。

## D31 文件校验基线由用户明确接受
- **决策**：完整性检查按需计算 SHA-256；记录或更新基线需要确认，不默认遍历整个库，不写原文件。
- **原因**：同名等长可以是不同内容；外部编辑造成的哈希变化不能直接判定为损坏。首次记录只能确认当前字节，不能证明它在记录前未损坏。
- **约束**：源路径/类型/版本及基线变化使旧结果失效；后台读取可取消，缺失/不可读/读取时变化分别报告。迁移保留已确认基线，不用新打包哈希静默接受来源变化；源路径仅映射至新素材库。

## D32 图片预设只保存参数，不保存素材与输出路径
- **决策**：图片预设独立保存在素材库 imagepresets.json，最多 20 个；选用只填参数，用户仍需明确开始处理。
- **原因**：固定交付规格可复用，参数迁移不应携带旧电脑输出目录或触发原件处理。
- **约束**：名称/格式/尺寸/质量共用校验；磁盘写入成功后才更新内存。损坏配置不空覆盖，明确恢复前保留并验证副本；迁移可选字段兼容旧包。

## D33 日常安卓交付关闭调试标记，保持签名和业务源码

- **决策**：新增 distribution 构建，继承 Debug 的配置和签名，明确关闭 isDebuggable，不启用 R8；Debug 继续供开发使用。CI 同时编译两者，只上传 Distribution，并检查实际 APK 调试标记、模块入口和广播 action。
- **原因**：2026-10-05 一加 Ace 3 Pro / Android 16 / Irena 1.9.2 (7249) 现场日志显示 `Failed to init instrumentation` → `Failed to init lsplant` → SIGSEGV，崩溃帧在 `zygisk_lsposed/zygisk/arm64-v8a.so`，发生在应用 onCreate 之前。原安装包与 M32 哈希一致，原环境下关闭调试标记的同源码包能启动并收发；不是通过停用模块换取启动。
- **依据**：Irena 1.9.2 所引用的 [LSPlant instrumentation 初始化](https://github.com/re-zero001/LSPlant/blob/bfb619aa049892d5f78b58fa69602bb3716efca5/lsplant/src/main/jni/art/runtime/instrumentation.cxx) 仅在 Java 可调试进程中安装相关 hook。旧包此前可用的具体环境变化尚未核实，不能据此断言所有 Android 16 或所有 LSPosed 都会失败。
- **实机验收**：同环境 Distribution 冷启动和搜索正常，素材快照、手动文字登记通过；微信后台两次复制分别约 42 ms / 63 ms 得到电脑登记回执，重复广播被去重。覆盖安装及强制停止后的无障碍状态必须现场复查；本次已重新开启并确认服务已连接。日志与配置备份只保留在本地忽略目录，不公开复制内容、设备地址或口令。
- **约束**：不修改 debug 的正式签名配置、Hook、评分、进程级 scope、循环防护或前台服务启停条件。不删除手机数据、不更换 Root 框架。Debug 编译通过和签名通过均不能代替真实设备冷启动；发包前必须检查 application-debuggable 并验签。

## D34 功耗优化保留即时基线与事件驱动

- 默认即时同步保留 CPU 保活行为；均衡模式是可选设置，只改变锁持有策略，不在意外 Disconnected 时停止服务。工作窗口 30 秒、长传输按进度续期，CPU 锁有 10 分钟保险期限；实际锁屏到达与省电幅度必须实机 A-B 验证。
- 持续局域网外部电脑交互使用 connectedDevice，声明对应前台服务权限及 CHANGE_NETWORK_STATE 前置权限。服务只保活，不捕获、不管理连接；网络路由监听与连接均由进程级 LanController 持有。参考 Android 官方前台服务类型说明。
- 重连失败计数不能绑在一次 Job 内；成功或显式目标切换才重置。无网络时停止尝试，恢复时立即尝试；纯局域网不依赖 INTERNET/VALIDATED 能力。
- MEDIUM 单消费者保留最新选中文本候选，尾沿兜底继续；HIGH 保持独立短延迟捕获。评分基线、隐私修订、回写防环和自动发送单消费者不变。
- Hook 文件异步读取最多 512 KiB+1，保持原复制时间；广播改字节并兼容旧 Base64。缓存重试来源不进入公开仓库，成功 / 记录淘汰 / 下次启动才清理本应用临时文件。
- HTTP 客户端共享资源，传输进程级且最多 2 个活跃、16 个在途；取消必须取消 Call，清理结束后才释放槽位。不能按页面销毁取消后台发送。

## D35 收发控制明确区分暂停和断点续传
- Android 暂停关闭 I/O 并保留重试来源，继续从头传输；取消才清理暂停任务缓存。暂停/取消状态不能被迟到失败或进度覆盖；实际登记成功若先完成，显示成功而不声称已撤回。
- PC 暂停为当前连接门闩，90 秒有限期限防止客户端已超时而服务端仍持有文件；取消与服务停止必须唤醒门闩并终止实际读写。文本回执和已进入登记阶段的文件没有可撤回按钮。
- 不改变两端 HTTP/WS 协议，也不声称字节偏移续传或跨进程恢复。未来续传必须成对实现文件身份/变化校验、偏移协商、部分文件保留及完整性确认。
- 目录调用只浏览已保存路径；Android 保存策略在 D36 按用户纠正统一目录。文件管理器兼容性需真机验证，Windows 自定义 EXE/参数通过 ArgumentList 传递且仅保存在当前电脑，不执行拼接 shell 命令。

## D36 安卓接收目录固定，打开位置不得调用目录选择器

- **决策**：所有新接收文件通过 MediaStore.Downloads 写入 `Download/Liuzhuan`，不再按类型分别写入 Pictures / Movies / Music。「打开接收目录」直接以 ACTION_VIEW + 目录 MIME + DocumentsProvider 文档 URI 启动系统文件浏览器；默认查询限定 MATCH_SYSTEM_ONLY，优先 DocumentsUI。可配置兼容的自定义管理器，但不改变保存位置。
- **原因**：用户明确要求统一接收位置并调用系统文件管理器浏览；M35 的 ACTION_OPEN_DOCUMENT_TREE 是目录选择/授权界面，不能作为浏览位置的替代。
- **约束**：禁止回退到目录选择或授权界面；无可用目录浏览处理器时明确提示更换应用。首次接收文件才创建目录，不预写占位文件、不请求全部文件权限。旧文件不自动迁移，任务原位置信息仍可打开；保留 IS_PENDING、流式下载、长度校验和未完成文件清理。
- **验证边界**：本地测试验证实际 Intent 分发与调用点固定路径，Debug / Distribution 编译及 lint 通过后交付；ROM 目录定位和图库索引属于实机验收，不能以测试替身代替。

## D37 手机作为 Wi-Fi 热点时仍是可用局域网

- **决策**：网络可用性合并 ConnectivityManager 的 Wi-Fi / 以太网 / VPN 路径与 Android 16 公共 TetheringManager 回调中的 Wi-Fi 共享接口。已开启热点在注册回调时立即更新；普通移动网络仍不单独启用局域网重连。
- **原因**：实际手机热点下两端端口可达，但手机只有 CELLULAR NetworkAgent，v1.8.4 将其误判离线，扫码后输出「等待局域网恢复」并阻止 WebSocket 连接。
- **约束**：使用已有 ACCESS_NETWORK_STATE 权限，不增加 Root、隐藏 API、额外权限或轮询。LanRouteState 串行合并两类回调，只在可用性改变时发布；客户端 Wi-Fi 断开不能覆盖仍开启的热点，热点关闭也不能覆盖仍可用的 Wi-Fi。保留进程级 scope、用户暂停、服务启停和配对鉴权。
- **依据**：[Android TetheringManager](https://developer.android.com/reference/android/net/TetheringManager)与[接口变化回调](https://developer.android.com/reference/android/net/TetheringManager.TetheringEventCallback)。支持范围与本项目 minSdk 36 一致；未改传输协议，不宣称断点续传。

## D38 历史连接只保存成功目标，历史口令单独加密

- **决策**：LanClient 收到当前 socket 的 welcome 后，在进程级 SupervisorJob / IO 保存目标。最多 20 个地址，身份为规范化 host + port，按连接时间排序。扫描、填入地址、失败/鉴权失败不新增历史，不添加协议字段。
- **持久化**：独立顶层 preferencesDataStore 委托避免同文件多实例。历史凭据用 Android Keystore AES-256 / GCM、随机 IV 与完整性标签加密；密钥生成串行，历史 UI 不显示口令。既有 SettingsStore 当前目标结构保留，本决策只加密新增历史字段。
- **恢复**：回忆历史时读取最新当前设置，只替换 host / port / password，沿既有 saveAndConnect 路径重连；保留省电、隐私和文件管理器偏好。存储失败不影响活跃连接，损坏历史不自动空覆盖；清空是用户确认后执行的独立操作。
- **边界**：删除历史不删除素材、不撤回当前目标设置、不断开当前会话。旧 IP 可能过期，设备恢复或密钥丢失时不能解密的口令需重新扫码。历史不提供远程网络、断点续传或跨电脑地址跟随。

## D39 手机麦克风首版独立明文通道，手动控制先于自动化

- **决策**：按用户“开始开发，先不做加密”实施独立明文音频 WS8902，短时单次随机邀请，不复用旧素材密码，不做长期音频配对。用户前台开启麦克风会话后，PC仅控制转发；停止转发不等于停采，结束会话才释放采集器。初版15分钟/闲置限制已按M41用户新要求取消，见D41。MicYou/AndroidMic/VoxMic仅作设计参考，无业务源码移植。
- **原因**：先交付可独立验证的采音→网络→显式虚拟设备输出链，避免把未经确认的 Codex 会话归属当成按钮事件。系统许可、取消和有界缓冲必须从第一版保留，加密和自动联动按后续阶段开展。
- **锚点**：`Services/Audio/*`、`Views/MicrophoneWindow`、Android `audio/*`。Kestrel仅用于新音频服务，不改变 D13 素材 HTTP 后端；保留 .NET7，NAudio固定2.2.1。
- **约束**：所有原剪贴板/素材链红线仍适用；原 connectedDevice 服务不代替 microphone FGS，麦克风模块不可停止原保活。未知/跨进程会话只观察，不自动开传输；断线/撤权/到期不能自动恢复录音。无原始音频落盘、无默认扬声器回退、无自研驱动或竞品整包依赖。
- **范围**：M39当时只验证本地构建与模拟端点；M40已通过原手机/虚拟驱动/Codex原听写现场验收，来电、锁屏功耗与其他ROM仍待专项验证。不能以一次手动成功替代自动联动或跨环境兼容验收。

## D40 音量可视化源于实际PCM，链路诊断不冒充虚拟麦克风

- **决策**：音量波形只来自实际采到的PCM16LE峰值/RMS，36点历史、可见时最高10Hz，无合成循环动画；界面同时标识采集帧和发送帧。原业务StateFlow与通知继续低频，不因波形逐帧刷新整页或后台通知。
- **本机试音**：用户显式前台开启、同一录音许可与单实例服务，60秒截止、CPU锁上限65秒；不创建网络连接，不转发、不落盘，结束仍释放原采集资源。PAUSE/RESUME不能冷启动录音。
- **电脑诊断**：显式“仅诊断收音”使用不输出的Sink，清晰说明Codex不可用；正常模式明确播放端/录音端方向。收到音频、电平非零、写入虚拟设备与Codex识别分别以对应证据确认。
- **依据**：现场首先发现旧设备无CABLE端点、音频服务未监听，手机显示连接失败；用户授权安装官方VB-CABLE后，实际回环和手机传音均通过，用户确认Codex原听写文字正常。首次成功不代替其他ROM、锁屏/来电、功耗和自动跟随验证。

## D41 一个二维码合并入口，音量门控与实验自动跟随各自保留许可边界

- **合并扫码**：旧素材字段保持顶层兼容，新增可选mic对象使用既有两分钟单次邀请。素材和音频依然独立鉴权/传输，扫码只连接素材并预填音频邀请，麦克风必须前台确认；过期/占用不能中断素材扫码，不把邀请存进设置或历史。
- **静音门控**：用户要求一定音量才转发。采用独立自写RMS门控，不把能量检测称作ASR或人声识别。默认标准-42dBFS，40ms开启、6dB迟滞、200ms开头/500ms尾音；保留灵敏/抗噪和连续传输。安静只发送1Hz状态/租约，读取批量100ms，保留实际采音和限时唤醒锁，不夸大电量收益。
- **持续待命**：按用户“麦克风保持开启后一直有效”，网络会话取消15分钟到期及闲置一分钟结束，停止转发/安静不结束采集。主动结束、连接中断、撤权/系统阻断仍清理；不允许断线或重启自动冷启动麦克风。本机试音保留60秒。CPU锁非引用计数、单次30分钟，健康会话每20分钟续期；不无限期持锁或堆积引用。
- **兼容协商**：welcome.data.silenceSuppression显式能力；旧电脑自动回退连续模式。当前代次status.quiet不能作为收音证据，安静清缓冲，恢复只认合法PCM；不携带quiet的旧手机继续原超时规则。仍是v1的向后兼容可选字段，两端成对修改。
- **自动跟随**：使用Windows原始GetProcessId返回码，只信S_OK；核验包家族、创建时间、路径并按会话实例去重。正值跨进程成功码不能归类为独立Codex，未知归属不可开启。空闲/活动/空闲校准后才可由用户启用，绑定当前手机连接编号与停止修订；手机暂停/结束、断线、设备异常和手动操作优先。无鼠标钩子、不读听写内容、不跨重启恢复许可。
- **COM边界**：会话枚举在独立MTA；使用唯一非类型化RCW，避免Windows共享MMDeviceEnumerator被自定义coclass类型绑定后导致NAudio下一次枚举InvalidCastException。回调有界入队，工作线程持有/释放接口；仅启用观察时核对状态。
- **依据**：[Windows会话注册](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-registersessionnotification)、[GetProcessId返回值](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol2-getprocessid)。现场已观察原听写在CABLE Output上的0→1→0独立Codex会话；完整自动转发、噪声/弱声和功耗仍按交付记录分别验收。

## D42 一次前台扫码完成素材和麦克风，主页保留可操作音波图

- **新要求优先**：用户明确要求一次扫码握手完成全部功能，替代D41正常流程“仅预填邀请、再到麦克风确认”的设计。扫码按钮和相机提示明确包含麦克风，系统录音权限仍需允许；有权限时直接在前台启动FGS，不再要求第二次扫码或电脑开始转发。后台重连/普通启动不复用该动作许可。

## D54 M54 大文件准入、回执索引与后台整理分别串行

- 页查询与整理工作器边界区分内部请求超时和父作用域取消：子请求超时显示可重试错误并释放等待者，工作器继续服务；真正父取消仍传播。没有自动重试轮询或新增保活锁。JVM替身与回环合成音频检查不作为真机耗电、弱Wi-Fi或听写验收。

## D58 音频读取证据与用户确认分开，恢复不接管Windows声音

- Core Audio设备/默认设备/音量事件驱动后台检查，750ms合并突发事件，无空闲周期扫描、试录或试播；设备变化不等于用户配错，正常耳机切换仅提示信息。麦克风窗口可见时的既有10秒体检与新常驻事件观察分别管理，关闭/退出应释放监听。

- 用户点击恢复后先核对原端点ID仍存在且活跃，只停止音频服务并保存流转设备选择；不按同名替换，不修改Windows默认、静音或音量，不恢复自动跟随、录音许可，不自动启动麦克风。系统配置变化提供明确提示及Windows声音入口；硬件失踪、驱动故障仍须系统排查，恢复档案不能修复声卡。
- 本地模拟/构建、真实输出计数、用户听写确认、实际扬声器外放与功耗测试各自成立；不得把一次配置检查表述为全链路验收。当前为本地交付，不推送GitHub或Releases。
